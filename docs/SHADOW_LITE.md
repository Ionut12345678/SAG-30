# Standalone SHADOW Lite — isolated prospective experiment

This is a minimal independent radar. It **does not** depend on the broken SAG-30 checkpoint/recovery/admission chain, does not alter frozen v0.3.3 or SAG-Crypto, and **never trades**.

- GitHub Actions `.github/workflows/shadow-lite.yml`: cron every 5 minutes Monday–Friday (GitHub cron is best effort, not a guaranteed 300-second start-to-start cadence), plus manual dispatch. The program checks 04:00–20:00 New York and daylight-saving time.
- Reads the existing `config/universe.csv`, requests Alpaca IEX stock snapshots in batches of 100 using existing `ALPACA_API_KEY` and `ALPACA_SECRET_KEY` repository secrets. If credentials/API/fresh prices are missing, emits `DATA_GAP` rather than pretending there were no opportunities.
- Candidate: a timestamped **latest trade** within 15 minutes, +5% to +10% relative to previous daily close. Up to 3 new tickers per cycle, ranked by observed change. The baseline is deliberately simple, not the existing complex SAG-30 BUY pattern.
- The **first_seen** is the time this workflow actually selected a symbol; it is never backdated. Persistent state is stored separately as `shadow-lite-state/shadow_lite/state.json` and updated with the GitHub contents API. One concurrency group serializes state updates. GitHub Actions report artifact contains the latest decisions.
- Tracks subsequently **observed trade prices** for 240 minutes, never an earlier session/day high. Milestones +15/+20/+30/+50 are measured against previous close strictly after first_seen. Missing later snapshots are censored. Quote spread, tradability, and halt are **UNKNOWN**; no actionability/BUY claim.
- No recovery of incident #567, no retroactive Gate 0 PASS, no entry into Gate 1. This is a **separate experiment**, not a replacement for the frozen audit protocol.
- Safety: zero orders; `SHADOW_WATCH_NOT_BUY` only. State JSON is bounded to 2,000 events, but the complete per-cycle report artifacts expire after 30 days; export evidence externally before expiry if a 10-session immutable audit is required. The state branch is separate from `radar-state`.
- Acceptance before calling this functional: merge this PR only after tests pass; verify one manual run with a fresh snapshot, successful state update, two successive real runs and post-detection outcome. A passing unit test alone does **not** demonstrate live functionality.
